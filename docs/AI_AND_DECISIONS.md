# 开发与 AI 使用记录

> 本文记录 WarpFit 0.2.0 的目标、关键取舍、AI 参与环节和人工核对边界。它是工程事实记录，不是申报书正文；参赛者对目标、路径和最终质量负责。

## 目标与边界

WarpFit 的目标是给 MoonBit 时序应用提供一条可直接嵌入的数值工作流：预处理 → 对齐 → 模板学习 → 聚类 → 分类 → 模型复用 → 子序列定位。边界是“有界预算的库 + CLI + 浏览器工作台”，不是通用时序平台：

- 不做 GPU、实时流、大规模索引、缺失值插值或自动确定原型长度。
- 不保证聚类全局最优；DBA 是局部迭代，初值会影响结果。
- 不宣称算法原创、性能领先或功能唯一；算法来自公开论文，重合与差异见 [RELATED_WORK.md](RELATED_WORK.md)。

## 关键取舍

1. **纯 MoonBit 核心，不调用 tslearn**：目标部署是 Wasm 与浏览器 Worker，不能引入 Python、numpy、scipy；核心只依赖 `moonbitlang/core`，同一份源码编译到 Wasm / Wasm-GC / JS / native。
2. **硬 DTW 与 Soft-DTW 分工**：硬 DTW 提供可复核路径，供聚类、分类和子序列定位；Soft-DTW 提供平滑目标与两侧梯度，供模板拟合。两者不是互相替代。
3. **距离专用两行 DP**：聚类分配和预测只需要距离，使用两行空间并只遍历窗口内格点；完整路径接口保留完整矩阵。`max_cells` 仍按完整逻辑矩阵保守计费，避免“省内存”变成“绕过预算”。
4. **模型保存预处理与对齐参数**：预测只把新样本分配给最近中心，不再训练；因此允许新批次只有一个样本或全部落在同一簇。模型文件经过严格 schema 和参数校验。
5. **结构化失败**：预算超限、空簇、未知字段、重复键、错误版本都返回明确的错误或退出码；不返回部分结果，也不把失败伪装成空结果。
6. **分类与选簇的语义**：`knn` 输出投票分布而不是概率；`select_k` 用平均轮廓系数在调用方给定候选内选择，空簇候选记为缺席，不推断候选外的 k。

## AI 参与与人工核对

AI 参与的环节：

- 代码草稿、测试补全、文档整理、重复性检查。
- 把验证输出整理成证据 JSON 和可复现命令。

人工核对的部分：

- 目标、范围与“不做什么”的边界。
- 数值语义：硬/软对齐的区别、DBA 局部性、分类输出不是概率、重采样不读取真实时间戳。
- 独立参考与交叉验证：全路径穷举、tslearn 对照、UCI 固定划分实验。
- 发布结论：CI 是否通过、Mooncakes 是否可安装、注册表消费是否真的通过；不以本地输出替代远程或注册表结果。
- 文档中的能力声明与限制是否一致；不把“实现存在”写成“已验证”。

## 验证闭环实际拦下的问题

以下问题均由测试、对照或 CI 先发现，再修复：

- `select_k` 成对距离预算的 Int32 累加溢出：32 × 512 × 16 的最坏情形会回绕为 0；改为 Int64，并在任何 DTW 计算前拒绝超限。
- 模型 / 预测数据文件被尾部附加字段拼成合法请求：改为每个文件先验证为单个完整 JSON，保留原文供核心检测重复键。
- 浏览器导入重复键被 `JSON.parse` 合并：改为在解析前做词法检查，保持与核心一致的拒绝行为。
- 不同平台数学库导致参考对照出现极小差异：对照使用明确容差，并记录最大绝对差，而不是要求逐位相等。
- 空簇、预算耗尽、Worker 取消：分别有明确错误/停止状态，避免返回不完整结果。

## 未完成事项

- 没有 GPU、实时设备接入、在线流、大规模索引或缺失值插值。
- 没有自动确定原型长度或无候选的簇数推断；`select_k` 只在给定候选内选择。
- 子序列定位当前只返回单个最佳区间，不支持窗口约束或 top-k。
- 真实数据实验是固定划分，不代表业务准确率或生产采用。
