# 核心机制与验收演示

以下说明对应当前代码，不要求背诵术语。先运行示例，再修改输入观察变化；展示时应能解释所用数据和边界。

## 一次完整演示

```text
node scripts/build.mjs
node bin/warpfit.mjs examples/align.json
node bin/warpfit.mjs examples/dba.json
node scripts/evaluate_holdout.mjs
moon run cmd/consumer --target js --deny-warn
```

约束对齐样例输出距离0；DBA样例的平均平方目标约0.166667降至0.118056。真实数据流程以16段早期记录训练，保存再加载模型，对16段不重叠后续记录分组；后续平均平方DTW代价在这一次固定划分中约135.35变为83.93。它不是人数分类准确率。最后的类型示例使用同一公共接口，运行完成打印 `warpfit_consumer_ok`。

## DTW到底做了什么

[dtw.mbt](../core/dtw.mbt) 先计算两个采样点之间的带权平方差，然后用动态规划选择总代价最小的单调路径。路径允许横、纵、斜向一步，因此不同节奏下的点可以对应。窗口限制允许出现的错位；等长窗口0仅允许对角线，但不等长窗口会沿较长轴延伸。把align样例的窗口从1改为0，平方代价会从0变为2。

需要画路径时使用完整DP矩阵；只需距离时保留两行并遍历允许格点。两种算法代价一致，不意味着窗口后可以忽略资源约束：本库仍按完整逻辑矩阵保守核对预算。

## DBA和聚类各自负责什么

[dba.mbt](../core/dba.mbt) 在当前模板与各条观测之间求DTW路径，再按对应位置和样本权重平均，更新固定长度模板；记录目标和停止状态。它是局部迭代，初始化不同可能得到不同结果。

[cluster.mbt](../core/cluster.mbt) 交替进行最近中心分配与每簇DBA更新。完全并列时选较小中心下标；空簇明确报错。最远点初始化只是确定性的初值策略，不是自动确定k，也不保证全局最优。

## 为什么保存模型后能处理单条新数据

[model.mbt](../core/model.mbt) 保存中心、预处理和对齐策略；预测只将每条新序列分配给最近中心，不再次训练，所以允许只有一条输入或全部新数据都属于同一簇。模型中的normalize=true代表逐序列独立标准化，不是沿用训练集均值。绝对温度或CO₂水平对任务重要时，直接消除它们可能不合适。

## 子序列和Soft-DTW的边界

[subsequence.mbt](../core/subsequence.mbt) 要求完整查询参与，目标端点开放，返回一个最佳连续区间；并列取最早结束位置。合法输入总有最佳区间，因此距离小不自动等于业务事件成立。当前没有子序列窗口、top-k或实时流索引。

Soft-DTW在所有路径的代价之间做平滑最小，用于计算输入梯度；校正项减去双方各自对齐自身代价的一半，自项梯度两侧都要计入。占用矩阵不是分类概率，行和不要求为1。详见 [数值语义](SEMANTICS.md)。

## 验证闭环实际拦下的问题

- `select_k` 的成对距离预算按 Int32 累加，32 × 512 × 16 的最坏情形会回绕为 0；改为 Int64，并在任何 DTW 计算前拒绝超限。
- 模型 / 预测数据文件尾部附加字段会被拼成合法请求；改为每个文件先验证为单个完整 JSON，并保留原文供核心检测重复键。
- 浏览器导入重复键会被 `JSON.parse` 合并；改为解析前做词法检查，保持与核心一致的拒绝行为。
- 不同平台数学库会让参考对照出现极小差异；对照使用明确容差并记录最大绝对差，而不是要求逐位相等。
- 空簇、预算耗尽、Worker 取消分别返回明确错误或停止状态，不返回不完整结果。

这些记录对应“开发与验证能力”要求中的“实际发现和防止错误”；详细命令与证据见 [VALIDATION.md](VALIDATION.md) 和 [AI_AND_DECISIONS.md](AI_AND_DECISIONS.md)。
